# 2026-02-01 OpenClaw 研究对话摘要

## 核心发现

### Memory Flush 机制澄清

Memory Flush 并非基于 Hook 系统实现，而是通过 `runMemoryFlushIfNeeded()` 直接函数调用实现。位于 `src/auto-reply/reply/` 目录，属于 Auto-Reply 子系统的核心功能。触发条件是上下文接近 token 限制时，系统触发特殊的 AI 调用周期。

**关键 Prompt 指令**：
```
"Store durable memories now (use memory/YYYY-MM-DD.md; create memory/ if needed)."
"If nothing to store, reply with __SILENT_REPLY__."
```

### 两套 Hook 系统对比

**Internal Hooks** (`src/hooks/`)
- 目标用户：最终用户、系统集成者
- 4 种事件类型：command、session、agent、gateway
- Bundled Hooks：session-memory、command-logger、boot-md、soul-evil
- 设计理念：简洁的事件广播

**Plugin Hooks** (`src/plugins/hooks.ts`)
- 目标用户：插件开发者
- 14 个扩展点，覆盖 Agent/Message/Tool/Session/Gateway 生命周期
- 支持优先级、结果合并、精细错误处理
- 设计理念：深度定制扩展
